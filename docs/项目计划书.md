## 一、项目概述与目标

### 1.1 项目概述

本项目以北京二手房市场为研究对象，基于 Kaggle 公开的北京链家二手房成交数据集（2011–2017 年，约 31.8 万条），设计并实现一个集数据可视化分析与房价预测于一体的 Web 系统。

系统采用 Django REST Framework 提供后端接口，Vue 3 + ECharts 构建前端界面，运用线性回归、决策树、随机森林、XGBoost 等多种机器学习模型进行房价预测，并通过 RMSE、MAE、R² 等指标完成模型对比与选型，最终实现面向用户的房价可视化分析与在线预测功能。

### 1.2 总体目标

完成一套可运行、可演示、可复现的房价预测与可视化分析系统，并形成完整的毕业论文与技术文档。

### 1.3 具体目标

1. 完成北京二手房数据的清洗与特征工程流程，形成规范化数据集。
2. 完成多模型训练、调优与对比实验，输出最优模型及完整评估结果。
3. 完成系统开发，实现数据管理、可视化分析、模型对比、房价预测四大核心功能。
4. 完成毕业论文一篇，并沉淀可复现的代码与文档。

| 模型序列化 | joblib（进阶可选 ONNX 加速推理） |
| 配置管理 | python-decouple + .env（密钥与数据库配置分离） |
| 依赖管理 | requirements.txt 锁定版本 |
| 行政区映射 | 13 编码 → 区名映射表（scripts/config/district_mapping.py），**不使用 GeoPandas/Shapely** |
| 开发工具 | VS Code / PyCharm |

### 3.2 分层架构

1. **表现层**：Vue 3 单页应用，负责图表展示与交互。
2. **接口层**：Django REST Framework 提供 RESTful API。
3. **业务层**：Django 各 app 实现数据管理、分析、预测等业务逻辑。
4. **数据层**：SQLite（默认）存储清洗后的数据与预测记录，可切换 MySQL。
5. **算法层**：离线训练脚本 + 在线推理服务。

### 3.3 关键设计原则

1. **训练离线、推理在线**：模型训练在独立脚本中完成，产出模型文件与指标文件；Django 启动时加载模型，接口只做推理。
2. **禁止请求内训练**：任何训练操作不得出现在请求处理路径中。
3. **防特征泄漏**：严格区分「预测时可得特征」与「成交后才知道的字段」。
4. **结果可复现**：固定随机种子，沉淀训练脚本与参数配置。

## 四、数据集说明与清洗策略

### 4.1 数据集概况

| 项目 | 内容 |
|---|---|
| 来源 | Kaggle 公开数据集（北京链家二手房成交数据） |
| 原始文件 | `data/new.csv`（GBK 编码，约 58.7 MB） |
| 规模 | 318,851 行 × 26 列 |
| 时间范围 | 2002-06 至 2018-01（主体为 2011–2017，约 31.8 万条） |
| 成交区域 | 13 个（链家成交区域，含**亦庄经开区**这一非行政区划单元；不含怀柔、密云、平谷、延庆等远郊区） |

### 4.2 字段分组

| 分组 | 字段 |
|---|---|
| 标识类 | url、id、Cid |
| 空间类 | Lng、Lat、district |
| 时间类 | tradeTime、constructionTime |
| 交易过程类 | DOM、followers |
| 价格类 | totalPrice、price、communityAverage |
| 房屋属性类 | square、livingRoom、drawingRoom、kitchen、bathRoom、floor |
| 建筑属性类 | buildingType、buildingStructure、ladderRatio、renovationCondition、elevator |
| 权益与配套类 | fiveYearsProperty、subway |

### 4.3 数据质量问题与处理策略

| 问题 | 具体表现 | 处理策略 |
|---|---|---|
| 年份零散 | 2002–2010、2018 记录极少 | 过滤，仅保留 2011–2017 |
| 乱码值 | livingRoom 含 `#NAME?` | 该行剔除或修正 |
| 串列错位 | drawingRoom 混入 `中 6`、`中 16` 等楼层值 | 剔除异常行 |
| 类型错误 | bathRoom 混入 `2006` | 剔除异常行 |
| 极端值 | price 最小 1 元/㎡，totalPrice 最小 0.1 万，square 最大 1745 ㎡ | 分位数截断或物理阈值过滤 |
| 缺失值 | DOM 缺失约 15.8 万条；buildingType 缺 2021；elevator/subway/fiveYearsProperty 各缺 32 | DOM 直接删除；其余少量缺失按众数填充或删除 |
| 建造年份含「未知」 | constructionTime 有 **19,283 条「未知」（占 6.05%）** | 按训练集内同小区中位数填充，详见 4.6 |

### 4.4 特征工程

1. **楼层解析**：`floor` 拆分为「楼层位置」（低/中/高/顶/底）与「总层数」两个字段。
2. **房龄构造**：`tradeTime 年份 − constructionTime` → `house_age`（边界规则见 4.6）。
3. **行政区还原**：`district` 为 1–13 的数字编码，通过**人工核对映射表**还原区名（取值仅 13 个，无需几何计算）。
4. **类别编码**：区名、装修、建筑类型、建筑结构等做类别编码，**具体字段与方式以 4.7 为准**（线性模型用独热编码，树模型用序数编码）。
5. **数值标准化**：对面积、房龄、梯户比等做标准化处理。
6. **距离特征**：距市中心（天安门）直线距离用 Haversine 计算（零成本，保留）；距最近地铁站距离**列为选做**，仅在取得站点坐标数据后实现，否则以 `subway` 布尔字段替代。
7. **特征选择**：基于相关性分析与模型特征重要性筛选。

### 4.5 特征泄漏风险清单（重要）

| 字段 | 风险 | 处理 |
|---|---|---|
| price | 与 totalPrice 存在数学换算关系（price = totalPrice × 10000 / square） | 预测总价时必须排除 |
| totalPrice | 预测单价时同理排除 | 预测单价时必须排除 |
| communityAverage | 小区均价本身接近目标值，构成泄漏 | **建模一律排除；本期不做对照实验** |
| DOM | 挂牌到成交天数，成交后才可得 | 从建模特征中排除 |
| followers | 成交后的关注热度，预测时不可得 | 从建模特征中排除 |
| url、id、Cid | 无泛化意义的标识 | 排除 |

### 4.6 清洗阈值（具体规则，唯一依据）

> 4.3 节仅用于描述数据问题的性质，**所有清洗实现一律以本节 4.6 的阈值为唯一依据**。4.3 中的「或」选项不再保留；如需调整阈值，直接修改本节并同步更新 scripts/01_clean_data.py 的配置区与实验记录。

| 字段 | 规则 | 依据 |
|---|---|---|
| tradeTime | 仅保留 2011-01-01 至 2017-12-31 | 数据主体区间，剔除零星年份 |
| square | 保留 10 ≤ square ≤ 500 ㎡ | 小于 10 ㎡无住宅意义，大于 500 ㎡多为异常记录 |
| totalPrice | 保留 10 ≤ totalPrice ≤ 5000 万元 | 剔除 0.1 万等明显错误值 |
| price | 保留 3000 ≤ price ≤ 150000 元/㎡ | 剔除 1 元/㎡ 等错误值 |
| livingRoom / drawingRoom / bathRoom | 转为数值，非数值行剔除；bathRoom ≤ 10 | 清除 #NAME? 型乱码、串列与异常编号 |
| floor | 非「低/中/高/顶/底」开头（含「未知」1,271 条、混入钢混/混合结构 32 条）→ floor_position 记为「未知」单独成类；total_floors 按训练集同小区中位数填充 | 保留楼层信息，避免整行丢弃 |
| house_age | 限制在 [0, 70]：< 0 视为缺失并按训练集同小区中位数填充；> 70 截断为 70 | 防止负房龄与异常值污染模型 |
| district | 样本量 < 3,000 的区（编码 3、5、12）在**可视化**时合并为「其他」并标注样本量；**建模保留独热编码不变** | 低频区样本不足，均价易被极端值拉偏 |
| buildingType | 取值 ∉ {1,2,3,4} 的行置空（含混入 ladderRatio 浮点值约 32 条）；缺失值在训练 Pipeline 内用**训练集众数**填充 | 清除串列污染；填充只用训练集，避免时序泄漏 |
| renovationCondition | 取值 0（26 条）置空；缺失值在训练 Pipeline 内用**训练集众数**填充 | 值域应为 1–4；填充只用训练集 |
| constructionTime | 「未知」按**训练集内**同小区中位数填充，仍缺失则按**训练集内**全区中位数填充 | 保留房龄信息，避免时序泄漏 |
| DOM | 整列删除 | 缺失约 50%，且属成交后信息 |
| buildingType | 缺失按众数填充 | 缺失仅 2021 条 |

> 所有阈值写入 `scripts/01_clean_data.py` 的配置区，便于调整与复现。

### 4.7 建模输入特征清单

| 特征 | 类型 | 处理方式 |
|---|---|---|
| square | 数值 | 保留，线性模型标准化 |
| rooms / halls / kitchen / bathrooms | 数值 | 保留 |
| floor_position | 类别 | 序数编码：**未知 = -1**（底=0 < 低=1 < 中=2 < 高=3 < 顶=4）；未知约 1,271 条（0.4%），单独成类，不参与序数距离 |
| total_floors | 数值 | 保留，标准化 |
| house_age | 数值 | 成交年份 − 建造年份 |
| renovation | 类别 | 独热编码 |
| building_type | 类别 | 独热编码 |
| building_structure | 类别 | 独热编码 |
| ladder_ratio | 数值 | 保留 |
| elevator / subway / five_years | 布尔 | 0/1 |
| district | 类别 | 按 `scripts/config/district_mapping.py` 映射为区名后独热编码（**不使用 GeoJSON / GeoPandas**） |
| dist_to_center | 数值 | Haversine 距离（km） |
| dist_to_subway | 数值 | **选做**：仅取得地铁站坐标数据后加入；否则剔除，以 `subway` 布尔字段替代（见 4.4 第 6 条） |
| lng / lat | 数值 | **不进入模型**，仅用于热力图与距离计算 |

**目标变量**：`total_price`（主）/ `unit_price`（对照）

**排除字段**：`price`、`community_average`、`DOM`、`followers`、`url`、`id`、`cid`（预测总价时 `unit_price` 亦排除，反之亦然）

## 六、算法方案与评估

### 6.1 目标变量策略

- **主目标**：`totalPrice`（总价，万元）——系统输出直观。
- **对照实验**：`price`（单价，元/㎡）——消除面积主导效应，体现建模深度。
- 两者互为换算关系，建模时必须互斥，不得同时作为特征。

### 6.2 模型集合

| 模型 | 定位 |
|---|---|
| 线性回归 | 基线模型 |
| 决策树 | 非线性对照 |
| 随机森林 | 集成方法，稳健 |
| XGBoost | 梯度提升，预期最优 |
| MLPRegressor（神经网络） | 非线性对照，参考同类项目做法 |

### 6.3 训练流程

1. 按 6.7 主口径做**时序划分**（2011-01 至 2016-06 训练，2016-07 至 2017-12 测试），固定随机种子。
2. 特征工程与预处理（编码、标准化）。
3. 各模型基础训练。
4. 超参数调优按 **6.6.1 约束**执行：统一 RandomizedSearchCV（n_iter ≤ 30）；交叉验证在训练集内用 `TimeSeriesSplit(n_splits=5)`，禁止普通 KFold。
5. 测试集评估与结果对比。
6. 选定最优模型，按版本命名序列化（如 `house_price_v1.joblib`），并导出指标 JSON。
7. 训练与评估脚本统一存放于 `scripts/` 目录，与业务代码解耦。

### 6.4 评估指标

| 指标 | 含义 | 方向 |
|---|---|---|
| RMSE | 均方根误差 | 越小越好 |
| MAE | 平均绝对误差 | 越小越好 |
| R² | 决定系数 | 越接近 1 越好 |
| MAPE | 平均绝对百分比误差（**在原始量纲（万元）上计算，反变换后取 y ≥ 10 万元的样本**） | 越小越好，房价预测最直观 |

> **朴素基线**：以「面积 × 该区训练集均价」作为对照基线。若模型未显著优于基线，说明未学到有效规律，需重新检查特征与泄漏。

### 6.5 模型选型原则

以测试集表现为准，综合 RMSE 与 R²；若差异不显著，优先选择结构更简单、推理更快、可解释性更强的模型。

### 6.6 超参数搜索空间

| 模型 | 超参数 | 候选值 |
|---|---|---|
| 线性回归 | — | 基线模型，无需调参 |
| 决策树 | max_depth / min_samples_leaf / min_samples_split | [3,5,7,10,None] / [1,5,10,20] / [2,10,20] |
| 随机森林 | n_estimators / max_depth / max_features / min_samples_leaf | [100,200,300] / [10,20,None] / [sqrt, log2, 0.5] / [1,2,5] |
| XGBoost | n_estimators / learning_rate / max_depth / subsample / colsample_bytree / reg_lambda | [300,600,900] / [0.03,0.05,0.1] / [3,5,7] / [0.7,0.8,1.0] / [0.7,0.8,1.0] / [1,3,5] |
| MLPRegressor | hidden_layer_sizes / alpha / learning_rate_init | [(64,), (128,), (128,64)] / [0.0001,0.001,0.01] / [0.001,0.01] |

### 6.6.1 调参约束（必读）

| 约束 | 规定 |
|---|---|
| 调参方法 | 统一使用 RandomizedSearchCV，n_iter ≤ 30 |

### 6.7 实验设置与可复现性

| 项目 | 设置 |
|---|---|
| 随机种子 | 42（numpy / random / sklearn 统一设定） |
| **数据划分（主口径）** | **时序划分**：2011-01 至 2016-06 训练（229,583 行，72.3%），2016-07 至 2017-12 测试（88,135 行，27.7%，约 7:3）。**禁止随机打乱** |
| **数据划分（对照口径）** | 另做一组随机划分实验，仅用于量化「时序 vs 随机」的指标差异，写入论文作为方法严谨性证据 |
| 评估口径说明 | 论文分两个口径报告：随机划分＝同分布预测能力；时序划分＝时间外推能力。避免笼统写成「泄漏」 |
| 交叉验证 | 训练集内部使用 TimeSeriesSplit(n_splits=5)，禁止普通 KFold |
| 调参方法 | RandomizedSearchCV（n_iter ≤ 30），详见 6.6.1 |
| 目标变量变换 | **绝对价格口径**：log1p 变换（偏度 4.72 为清洗前、**2.99 为清洗后训练集内**；清洗后 max=4900 万）。**相对价格口径（ratio）**：偏度 0.996 接近正态，**不做变换**。评估时统一反变换回原量纲 |
| 标准化 | 线性回归与 MLP 必须标准化；树模型不需要 |
| 类别编码 | 线性模型用独热编码；树模型用序数编码 |
| 防泄漏 | 所有预处理（编码、标准化、缺失填充）封装进 sklearn Pipeline，**仅在训练集 fit**；同小区中位数等填充统计量同样只能由训练集计算 |
| 实验记录 | 记录模型名、版本、参数、指标、训练耗时 → metrics_v1.json |
| 稳定性验证 | **仅对最终选定的 1 个模型**做 3 种子重复实验，报告均值 ± 标准差；不参与调参 |

### 6.7.1 三层评估设计（ES-1 / ES-2 / ES-3）

时序划分下训练集与测试集价格水平差异显著（单价中位 33,701 → 57,479，**1.71 倍**；测试集 35.25% 的样本高于训练集 p95）。树模型无法外推，若只用「时序划分 + 绝对价格」评估，五模型将集体失效、无法对比。因此设三层递进评估：

| 编号 | 划分 | 目标变量 | 评估目的 | 预期结果 |
|---|---|---|---|---|
| **ES-1** | 随机划分 8:2 | log1p(总价) | 同分布预测能力：模型是否学到「特征 → 价格」映射 | 指标好 |
| **ES-2** | 时序划分 | log1p(总价) | 时间外推局限：暴露价格水平漂移的影响 | 指标显著下降（如实报告） |
| **ES-3** | 时序划分 | **相对价格 ratio = 单价 ÷ 当年该区成交中位单价** | 相对估值能力：模型真实价值所在 | 指标回升 |

**ES-3 的两条强制要求**：

1. **必须还原回绝对价格再报误差**：ratio 预测值 × 当期该区中位单价 → 换算回元/㎡，再计算 MAE / MAPE。否则 ratio 口径与绝对口径的 R²/RMSE 不可比，会被质疑「换口径刷指标」。
2. **论文必须写明业务前提**：ES-3 预测的是「相对当期行情的估值」，绝对价格需要输入当期该区行情中位价（可从最新成交实时计算）。系统接口相应增加该输入项（见 12.4）。

**ES-3 的实际效应（2026-10-21 实测订正）**：归一化确实中和了区级与年际的价格水平差异，但特征重要性的实际变化与最初预期相反 —— `square` 由 0.3635 降至 0.1197（面积效应被 ratio 除掉），而 `district_name` 由 0.1104 升至 0.1337、`dist_to_center` 由 0.2226 升至 0.3283。原因：同区内不同房源相对行情的偏离仍与区位细分强相关。论文讨论须按实测结果表述。

> **统一评估口径（2026-10-21 补充）**：ES-1/ES-2 的原生 R² 在总价（万元）量纲上计算，ES-3/ES-4 在单价（元/㎡）量纲上计算，二者不可直接比较。为此所有实验统一补充 `r2_unit`（还原为单价后计算），论文主表使用 `r2_unit`，原生口径 R² 仅作副列。

### 12.4 预测接口约定（草案）

**请求** `POST /api/v1/predict/`

| 字段 | 类型 | 说明 |
|---|---|---|
| square | float | 建筑面积（㎡） |
| district | string | 行政区名称 |
| floor_position | string | 楼层位置（低/中/高/顶/底） |
| total_floors | int | 总层数 |
| house_age | int | 房龄（年） |
| rooms | int | 卧室数 |
| renovation | string | 装修情况 |
| elevator | bool | 是否有电梯 |
| subway | bool | 是否近地铁 |
| five_years | bool | 是否满五年 |

**响应**

```json
{
  "predicted_total_price": 385.6,
  "predicted_unit_price": 46300,
  "model_version": "total_price_xgb_v1",
  "currency": "CNY",
  "unit": "万元"
}
```

> 说明：predicted_unit_price 由 predicted_total_price 折算得出，公式为 **预测总价（万元）× 10000 ÷ 建筑面积（㎡）**。单价不作为模型目标变量，仅用于展示，避免与 4.5 节的泄漏排除规则冲突。

> **ES-3（相对价格口径）补充输入**：若系统采用 ratio 口径模型，预测请求需额外传入 `market_median_unit_price`（该区当期成交中位单价，元/㎡），最终价格 = ratio 预测值 × market_median_unit_price。该参数可由系统按最新成交数据自动计算并提供默认值。

### 12.5 与主对标项目的差异

| 维度 | 主对标项目 | 本项目 | 说明 |
|---|---|---|---|
| 模型数量 | 单模型推理 | 五模型对比 + 调优 | 强化，论文核心 |
| 特征泄漏治理 | 未体现 | 显式清单管控 | 强化，保证结论可信 |
| 模型版本与指标留档 | 二进制直接入库 | 版本命名 + 指标 JSON | 强化，可复现 |
| 用户模块 | 注册/JWT/验证码/个人信息 | 不做 | 弱化，聚焦主线 |
| 数据规模 | 爬虫量级 | 31.8 万条 | 优势 |
| 可视化 | 大屏 | 大屏 + 房价热力图 | 小幅增强 |
