## 三、⚠️ P1：预测区间标称 80%，实测覆盖率仅 56.6%

### 3.1 实测

加载部署模型，在测试集抽 4,000 条，按接口同样的逻辑（逐树 p10–p90 → clip → 含点预测）计算：

| 指标 | 数值 |
|---|---|
| **标称水平** | 0.80 |
| **实测覆盖率** | **56.60%** |
| 区间宽度中位 | 11,588 元/㎡（相对均值 20.1%） |

即：界面写「80% 经验区间」，但**只有约 57% 的真实价格落在区间内**。答辩被问「80% 怎么来的」时无法自圆。

### 3.2 原因

随机森林逐树预测的离散度**系统性低估**真实不确定性：树之间高度相关（bootstrap 重叠 + 同一数据），树间分歧远小于真实残差。这不是实现错误——树离散度在自身数据上也只有 52.9% 覆盖，说明该偏差可在训练期内自检出来。

正面性质（值得保留）：区间宽度随输入条件变化（房龄 60 年收窄到 50.2%，300㎡ 拓宽到 82.3%），是条件区间而非常数区间。

### 3.3 修复方案（已实测验证）

**残差分位校准**：训练期最后半年（2016-01 ~ 2016-06，45,865 条）留作校准集，模型在校准集上的残差取经验分位 q10 = −0.146 / q90 = +0.202，构造区间 `pred + [q10, q90]`：

| 方法 | 覆盖率 | 宽度中位 |
|---|---|---|
| 现状（树离散度 p10–p90） | 56.79% | 12,513 元/㎡ |
| 树离散度 p1–p99 | 81.69% | 24,803 元/㎡ |
| **残差分位校准（加性）** | **78.87%** | **19,339 元/㎡** |
| 残差分位校准（乘性） | 77.94% | 19,562 元/㎡ |

推荐**加性残差校准**：覆盖率与标称 80% 一致，宽度比 p1–p99 方案窄 22%。

落地要点（改动集中在训练脚本，约 20 行）：
1. `04_tune.py` 最终拟合时**预留训练期最后半年不参与训练**，拟合后在该段算残差分位，把 `q10/q90` 存入模型包 metadata；
2. `predictor.py` 区间改为 `ratio ± [q10, q90]`（保留 clip 与含点预测保险）；
3. `interval_level` 保留 0.8（此时名实相符），前端文案「80% 经验区间」改为「80% 校准区间」；
4. 接口文档 3.1 节的「不是校准后的置信区间」改为「经训练期留出段校准，实测覆盖率 78.9%（见论文 6.x）」。

若不想重训：用 `oob_score=True` 的 OOB 残差近似校准分布，不用留出段，但时序混合略有漂移，毕设可接受。

## 四、P2 建议（6 项，不阻塞）

1. **计划书缺预测区间描述**：接口已返回 `interval_*` 5 个字段、前端已展示，但计划书（v1.5）全文无「预测区间/不确定性」章节。答辩问区间的理论依据时顶层文档无法支撑——建议在 6.8 后补一小节（0.5 页即可，校准方法 + 实测覆盖率直接可写进论文）。
2. **`r2` 字段仍跨口径**：`metrics_tuned_v1.json` 中 ES1/ES2 的 `r2` 是 log 总价口径（0.751 / 0.288），ES3 的 `r2` 是单价口径（0.866）。前端因只读 `r2_unit` 而正确，但其他消费者会踩坑——建议加 `r2_target` 字段显式声明每个 `r2` 的口径。
3. **ECharts 651 KB（gzip 216 KB）仍全量**：五页面只用 bar/line/scatter/heatmap，按需注册可减 60% 以上。
4. **`/meta/options/` 1.39 s 且无缓存**：每次进预测页都全表 distinct + 按年聚合 + DataFrame。数据是静态的，加模块级缓存（首次计算后复用）可降到毫秒级。
5. **前端测试覆盖薄**：6 个用例只覆盖工具函数，图表 option 组装、预测表单联动、useAsync 错误分支均无测试——至少给 useAsync 和 BaseChart 的降级逻辑各补 1 个用例。
6. **概览页年度趋势图图例与「2017 政策节点」标注重叠**（截图右上角），调 legend top 或标注位置即可。
