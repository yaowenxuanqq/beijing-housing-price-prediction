## 一、选题背景与意义

### 1.1 研究背景

房价是关系国计民生的重要经济指标，也是居民置业决策的核心因素。房价受区位、面积、房龄、楼层、朝向、装修、交通配套以及宏观经济政策等多种因素共同影响，具有明显的非线性与多维度特征，传统线性定价方法难以准确刻画其形成规律。

北京作为超大城市，其二手房市场交易活跃、数据积累充分，具有典型研究价值。随着大数据与机器学习技术的发展，利用历史成交数据构建房价预测模型已成为研究热点，但多数同类研究止步于模型训练与指标对比，缺少面向实际使用的完整系统实现。

### 1.2 研究意义

**理论意义**：通过在同一数据集上构建并对比线性回归、决策树、随机森林、XGBoost 与神经网络五种模型，系统考察不同算法在房价回归问题上的适用性与性能差异，为同类回归预测问题提供方法参考；同时显式处理特征泄漏问题，提高模型评估结论的可信度。

**应用意义**：构建集数据可视化分析与在线房价预测于一体的 Web 系统，帮助购房者、房产中介与投资者直观了解房价水平及其主要影响因素，为购房决策提供参考；系统输出结果附带模型版本，便于结果追溯。

## 二、国内外研究现状

### 2.1 国外研究现状

国外房价研究起步较早，早期以特征价格模型（Hedonic Price Model）为代表，通过将房屋属性作为自变量建立回归模型解释价格构成。随着机器学习发展，研究逐步转向随机森林、梯度提升树、支持向量机与神经网络等非线性方法。Kaggle 平台举办的房价预测竞赛推动了大量特征工程与模型调优实践，形成较成熟的建模范式。

### 2.2 国内研究现状

国内学者结合国内城市数据，采用线性回归、支持向量机、XGBoost、LSTM 等方法开展房价预测研究，并逐步将预测模型与可视化系统相结合。近年开源社区也出现了一批「爬虫采集 + 数据清洗 + 模型预测 + 可视化展示」的完整项目，技术路线趋于成熟。

### 2.3 现有研究的不足

通过对 GitHub 上 7 个高相关开源项目的调研，发现以下共性问题：

1. **模型对比不充分**：多数项目仅使用单一模型（如线性回归或随机森林）直接部署，缺少多模型系统对比。
2. **特征泄漏处理缺失**：普遍未识别「成交后才可得」的字段（如小区均价、成交周期、关注人数）与目标变量的数学换算关系，导致评估指标虚高、结论不可信。
3. **工程规范薄弱**：模型二进制文件直接入库、依赖版本不锁定、密钥硬编码，实验难以复现。
4. **研究定位模糊**：部分项目堆砌 Hadoop、Spark、知识图谱等名词，但与房价预测主线关联弱。

### 2.4 本课题的切入点

本课题在成熟技术路线基础上，重点补齐上述不足：以特征泄漏治理为前提，开展五模型系统对比与超参数调优；采用规范工程实践（配置分离、模型版本化、指标留档）保证结果可复现；聚焦北京二手房市场，避免区域特征混杂。

## 三、研究目标与研究内容

### 3.1 研究目标

以北京链家二手房成交数据为对象，设计并实现一个基于机器学习的房价预测与可视化分析系统，实现数据的可视化探索分析、多模型训练与性能对比，以及面向用户的在线房价预测功能。

### 3.2 研究内容

**（1）数据获取与预处理**

以 Kaggle 公开的北京链家二手房成交数据为数据源（2011–2017 年，318,851 条记录、26 个字段）。针对数据存在的年份零散、乱码值、串列错位、极端值与缺失值等问题，建立脚本化、参数化的清洗流程：

| 问题 | 处理策略 |
|---|---|
| 2002–2010、2018 年零散记录 | 过滤，仅保留 2011–2017 |
| livingRoom 含 `#NAME?` | 剔除异常行 |
| drawingRoom 混入楼层值 | 剔除异常行 |
| bathRoom 混入年份值 | 剔除异常行 |
| price/totalPrice/square 极端值 | 分位数截断或物理阈值过滤 |
| DOM 缺失约 15.8 万条 | 删除该字段 |
| buildingType 缺失 2021 条 | 众数填充 |
| constructionTime 含「未知」 | 按小区中位数填充或单独编码 |

**（2）特征工程**

- 楼层解析：将 `floor` 拆分为「楼层位置」与「总层数」
- 房龄构造：成交年份 − 建造年份
- 行政区还原：以经纬度与北京行政区划 GeoJSON 做点面判断，将数字编码还原为区名
- 距离特征：距天安门直线距离（Haversine 公式）、距最近地铁站距离（站点坐标 + KDTree 最近邻）
- 类别编码与数值标准化
- 特征选择：基于相关性分析与模型特征重要性

**（3）特征泄漏治理**

建立泄漏字段清单并严格排除：`price` 与 `totalPrice` 因存在数学换算关系而互斥；`communityAverage`（小区均价）接近目标值；`DOM`、`followers` 为成交后才可得；`url`、`id`、`Cid` 为无泛化意义标识。

**（4）多模型构建与对比**

构建线性回归、决策树、随机森林、XGBoost、MLPRegressor（神经网络）五个模型，采用 5 折交叉验证与 GridSearchCV 进行超参数调优，以 RMSE、MAE、R² 为指标在统一测试集上对比，选出最优模型。

**（5）系统设计与实现**

采用 Django 5 + Django REST Framework 构建后端接口，Vue 3 + Element Plus + ECharts 构建前端界面，实现数据管理、可视化分析、模型对比与房价预测四大核心模块。

### 3.3 拟解决的关键问题

1. 如何建立可复现的数据清洗流程，处理乱码、串列、极端值与缺失值。
2. 如何识别并规避特征泄漏，保证模型评估结论可信。
3. 如何在缺少编码映射表的情况下还原北京行政区名称。
4. 如何在统一实验条件下公平对比五个模型并完成选型。

## 四、研究方法与技术路线

### 4.1 研究方法

- 文献研究法：梳理房价预测与机器学习相关研究
- 实验研究法：多模型对比实验与超参数调优
- 系统工程法：按分层架构完成系统设计与实现
- 对比分析法：横向对比同类开源项目的功能与架构

### 4.2 技术栈

| 层次 | 技术选型 |
|---|---|
| 后端 | Django 5 + Django REST Framework |
| 后台管理 | Django Admin |
| 前端 | Vue 3 + Element Plus |
| 可视化 | ECharts |
| 数据库 | MySQL 8（开发期可用 SQLite） |
| 数据处理 | pandas + numpy |
| 机器学习 | scikit-learn + XGBoost |
| 地理处理 | GeoPandas / Shapely |
| 配置管理 | python-decouple + .env |

### 4.3 技术路线

数据获取 → 数据清洗（年份过滤、异常值处理、缺失值填充）→ 探索性数据分析 → 特征工程（楼层解析、房龄、行政区还原、距离特征、编码、标准化）→ 特征泄漏排查 → 五模型训练与超参数调优 → 统一测试集评估与对比 → 最优模型序列化与指标导出 → Django 后端接口开发 → Vue 前端与可视化开发 → 系统联调与测试。

### 4.4 系统架构

1. 表现层：Vue 3 单页应用，负责图表展示与交互
2. 接口层：DRF 提供 RESTful API
3. 业务层：Django 各 app 实现数据管理、分析、预测逻辑
4. 数据层：MySQL 存储清洗后数据
5. 算法层：离线训练脚本 + 在线推理服务（训练离线、推理在线，禁止请求内训练）

### 4.5 系统功能模块

| 模块 | 主要功能 |
|---|---|
| 数据管理 | 数据导入、预览、缺失值与异常值统计、清洗结果对比 |
| 可视化分析 | 房价分布、各区均价、面积价格关系、特征相关性热力图、特征重要性、房价热力图 |
| 模型对比 | RMSE/MAE/R² 对比、预测值 vs 实际值散点图、残差分布 |
| 房价预测 | 输入房屋特征，输出预测总价、折算单价与模型版本 |
| 报表导出 | 分析与预测结果导出（可选） |

## 六、特色与创新点

1. **显式特征泄漏治理**：建立泄漏字段清单并排除，避免指标虚高，同类项目普遍缺失该环节。
2. **五模型系统对比**：在同一实验条件下对比线性模型、树模型、集成模型与神经网络，对比维度完整。
3. **离线距离特征构造**：在不依赖第三方 API 的前提下，用 Haversine 与 KDTree 构造距离特征，兼顾效果与成本。
4. **工程可复现性**：配置与密钥分离、模型版本化命名、指标 JSON 留档、特征列清单冻结。
5. **训练与推理解耦**：训练离线完成，系统仅做在线推理，保证接口响应性能。
